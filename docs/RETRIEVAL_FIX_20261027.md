# 2026-10-27 多关键词问答检索修复

## 问题与原因

在相同的2000条CSV样本上，输入“北京 Python 数据分析岗位需要哪些技能？”时，旧版返回59条结果，前五条是文案、供应链、公关和广告岗位，模型因此报告材料不足。

旧版仅要求多个明确关键词中的任意一个命中；“数据分析”又会额外获得岗位方向得分，导致不含Python的岗位占据前五条。检索文本还遗漏了job_category，无法利用“数据分析”分类识别业务分析、用户增长分析等岗位。

## 实际修改

- 同一条岗位必须同时满足识别出的多个核心关键词，再进行评分和统计；扩展其他城市时也保留全部关键词。
- 岗位类别job_category加入检索文本及问答返回记录，并随岗位证据传给模型；类别只用于上下文，引用仍必须来自原始job_description或skills。
- 岗位描述、技能、原文引用校验与明确的失败回退保留。本次没有修改CSV或让模型补写岗位原文。

## 验证范围

新增5项回归检查先在旧版全部失败，修复后全部通过。后端完整78项自动检查通过，Python 3.10语法解析通过。模型分支使用模拟HTTP响应，真实提供方请求为0；这些结果不能写成线上真实模型准确率。

本地重放同一问题后只保留3条北京岗位：JOB_0582（数据运营分析师）、JOB_1351（用户增长分析师）、JOB_1962（业务分析实习生）；三条类别均为数据分析，技能均包含Python。原深圳Java后端示例仍匹配7条。还重放了广州、杭州、JavaScript、Java与Spring Boot组合及无匹配问题；逐项结果见qa_retrieval_fix_20261027.json。

记录以已推送的b04fa746e270f6f2d2e9f03569fc75d1b7449d5c为修复基线。原2026-10-26的真实调用记录及16页技术文档保留其当时的版本和测试范围；本记录补充本次修复。实际发布与真实模型复测以新提交和Render状态为准。
