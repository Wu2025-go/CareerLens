# CareerLens 0.8.1 RAG 回答补修

用户在本机配置模型后，0.8.0 页面显示了模型生成与引用摘录。这证明该次调用链路可用，但人工对照样本后发现两类需要改进的行为。

## 本次修复

1. 模型曾输出“三个深圳 Java 后端样本都要求 Java 基础”。引用的 JOB_0053 技能列没有 Java，岗位描述也没有明确列出 Java 基础要求；其岗位名称含 Java。仅凭岗位标题或部分岗位摘录，不能推出全体样本均明示某项要求。本版提示词要求只描述被引用岗位能证明的内容，并用保守规则过滤“岗位都要求”“样本均涉及”“所有岗位需要”等明确全称断言。
2. 同一段引用同一岗位的两条不同摘录时，正文曾显示两次同一编号。本版正文每个岗位只展示一个引用入口，悬停可查看不同摘录；下方完整引用摘录仍逐条保留。不是删除第二条证据。
3. 回答内直接显示本次数据范围和数据版本，滚动后仍能分辨实采与混合测试。
4. 修正文档中数据文件短版本的笔误：SHA-256 前 12 位是 `f654f5116218`，数据文件本身没有修改。

命中数仍由完整筛选结果计算；模型参考的是最多 5 条检索证据。当前深圳、后端开发、Java 条件下：实采范围命中 3 条，混合测试范围命中 19 条。重新打开页面默认回到实采范围，不是模型只能读取 3 条数据。

## 过滤行为与限制

- 先验证返回结构、引用编号和逐字摘录，再检查明确的全体岗位断言。
- 部分段落被过滤时，保留其他通过检查的段落，只保留这些段落使用的引用，并在页面说明隐藏段落数量；不改写模型原句来伪装为正确结论。
- 全部段落被过滤时，明确回退为规则检索，状态为 `unsupported_generalization`。
- 技能频次、样本数量和薪资仍由程序统计。
- 规则只覆盖明确措辞，不是完整语义验证，也不能保证其他句式没有事实错误。真实模型多题评测仍需人工对照原文。

## 使用更新包

1. 在原启动终端按 Ctrl+C 停止服务。
2. 先保留旧目录备份，再将更新包中的文件合并覆盖到原来的完整 `CareerLens-repo` 根目录。
3. 保留自己电脑上的 `.env`；更新包不含真实密钥或账号数据库，不必重新配置已经保存的密钥。
4. 在项目根目录执行 `python scripts/start.py`，让前端重新构建。
5. 浏览器按 Ctrl+F5 刷新，重新发送岗位技能问题。正文同一段同一编号应只显示一次，回答下方应显示数据范围。
6. 配置正确且模型有可用输出时显示 RAG；全部结论被拒绝时显示明确的规则回退，不能把这种情况标成模型生成成功。

本次自动测试使用模拟模型 HTTP 响应，不发送真实密钥，不产生真实模型调用。源码内旧版 Word 和 JSON 验收记录按原版本保留，不能充当本次新补丁的线上验收。

本地检查结果：后端运行 147 项，其中 146 项通过、1 项独立 Postgres 检查跳过；前端 13 项通过；50 条固定统计问题通过；前端生产构建通过。语义规则不构成大模型准确率证明。

如需留存一次本机真实调用记录，可在服务运行时执行：

```powershell
python scripts/check_ai.py --dataset-scope all --output docs/qa_live_0_8_1_all.json
```

这条命令会发出一次问答；配置有效且检索有证据时会调用模型。输出保留数据范围、版本和引用等信息，不含密钥。脚本默认 real，要测试 1 万条范围需明确加 `--dataset-scope all`。记录中的引用校验通过仍需要人工对照结论。
