## 二、统计计算口径

薪资沿用项目 CSV 约定：数值 ≥1,000 时按元/月转为 K/月，其余按 K/月。先取每条有效薪资区间的中点，再求均值或中位数。统计问答使用 Decimal 并四舍五入到两位；首页和原图表仍按一位显示。它们不是实发工资、薪资预测或企业报价承诺。

统计数量覆盖全部满足条件的记录，和只展示 5 条证据或 10 条推荐无关。占比分母保留城市、学历、招聘类型、薪资条件，去掉岗位类别和关键词；页面明确展示分母。统计不会自动扩展城市，以免把别处样本说成目标城市结果。

时间图是岗位**发布日期的样本分布**，没有连续采集证据，不能直接称为市场增长率。现有数据没有投递人数、招聘名额和录用率，不能估计竞争程度。

## 三、本地验收顺序

1. 在项目根目录运行 `python scripts/start.py`，保持终端打开，访问 `http://127.0.0.1:8000`。
2. 默认“实采样本 · 正式分析”应显示 2,000 条，能看到来源限制、发布日期范围和版本。
3. 在就业问答直接发送“北京数据分析岗位的平均薪资是多少？”：应有 20 条样本，均值 12.42K/月、中位数 13.48K/月，标记为程序统计。
4. 发送“北京和上海数据分析岗位的薪资比较”：应分别显示北京 20 条、上海 11 条，保留各城市样本量。
5. 发送“杭州内容运营实习岗位有多少？”：实采范围应为 2 条。发送“杭州运营岗位有哪些？”应先确认类别。
6. 到推荐或测评页，选择内容运营，检查出现 SEO、Photoshop 等本类技能。清空个人技能时可浏览岗位，不应显示默认 50% 个人匹配。
7. 切换“全部样本 · 混合测试”后页面变为测试提示；再次直接提问北京数据分析均薪，应为 109 条、14.37K/月。此结果不可作为真实市场结论。正式演示结束前切回实采范围。
8. 直接打开并刷新 `/ask`、`/skills`、`/recommend`、`/trends`、`/history`；无结果筛选应显示空状态。手机视图和最后部署页面需要团队实际浏览器复核。

比较题只展示所提城市；由于跨页面筛选器目前一次只选一个城市，比较卡片不提供容易丢失城市条件的直接跳转按钮。

## 四、自动检查

```bash
python scripts/validate_jobs.py
python scripts/evaluate_questions.py --output docs/STATISTICS_EVALUATION_0_8_0.json
node --test frontend/tests/*.test.js
npm --prefix frontend run build
```

后端完整测试先在单独终端启动 `backend.main:app` 的 8000 端口。测试请设 `CAREERLENS_ANSWER_MODE=rules`，避免发出真实付费模型请求。

```powershell
$env:CAREERLENS_ANSWER_MODE="rules"
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

另一个终端：

```powershell
$env:CAREERLENS_ANSWER_MODE="rules"
python -m unittest discover -s tests -p "test_*.py" -v
```

本地数据校验和 50 条固定统计句式回归记录随源码保存。后端真实 Postgres 检查需要独立测试库；不得把生产 `DATABASE_URL` 当作测试库。CI 配置已有单独 Postgres 容器。

本次不调用真实大模型，也不重新核验旧版的真实调用记录。引用编号和摘录校验不等于回答语义正确，不能写“杜绝幻觉”。

## 五、更新 GitHub 与 Render

建议使用更新包覆盖**原来带 `.git` 的仓库目录**，不是把只有补丁文件的文件夹新建成完整项目。覆盖前保留原目录备份，更新包不含 `.git`、真实 `.env`、本地数据库、虚拟环境和依赖目录。

本地确认后，在原仓库终端检查并创建更新分支：

```powershell
git status --short
git switch -c feature/national-data-statistics
git add backend frontend/src frontend/tests scripts tests data docs README.md START_HERE.md .env.example .github/workflows/ci.yml
git --no-pager diff --cached --stat
git commit -m "Add dataset provenance and full-sample statistics"
git push -u origin feature/national-data-statistics
```

提交前检查文件清单，不应包含密钥或账号数据库。打开 GitHub 创建 Pull Request，待 CI 通过再合并 `main`；如果本地已有同名分支，先确认当前分支状态，不要反复执行创建命令。

Render 原有构建和启动方式可继续使用：

```bash
# Build Command
pip install -r requirements.txt && npm --prefix frontend ci && npm --prefix frontend run build
# Start Command
python -m uvicorn backend.web:app --host 0.0.0.0 --port $PORT
```

发布后核对 Deploys 中的提交，再检查 `/health` 显示 `0.8.1`、`/api/dataset` 默认 2,000 条且版本为 `f654f5116218`、刷新子页面不报 404。应用发布不会续期数据库；账号库状态应在 Render 单独确认。比赛提交包应取最终合并后的完整源码，不能用只含改动文件的更新包代替。
